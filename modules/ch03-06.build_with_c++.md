# 使用C++进行单片机开发

对于主流的单片机来说，使用C语言进行开发仍然是主流，常见的大型项目如下所示。

💡 驱动库，如ST的HAL库  
💡 RTOS库，常见的FreeRTOS、ThreadX、RT-Thread  
💡 图像库，常见的LVGL、Emwin  
💡 协议库，常见的LWIP、tinyusb  

这些都是典型的C语言开发的单片机项目，也是整个单片机系统构建的基石。

不过使用C++开发，也为嵌入式开发带来另一种选择，相比于C来说，有如下的优点。

💡 具有更好的代码组织能力，使用类可以更容易的进行数据和方法的抽象，比起C语言通过结构体和函数指针的方式简单  
💡 使用静态变量和模板元编程可以实现零成本抽象，不会增加运行时开销
💡 具有更好的类型安全，对于很多转换需要强制处理，具有更强的安全性  
💡 使用RAII可以非常方便的管理资源的释放，避免C语言多返回出口时的管理难题

不过在使用C++开发时，就需要解决C/C++混合编程的问题，这个将在本节进行说明。

## C/C++混合编程的实现

对于现代单片机开发的主流工具，iar、keil、gcc来说，都已经天然支持了C/C++混合编程，不过仍然有些区别需要注意。

1. 编译器使用c++的方式编译`.cc/.cpp`文件、C的方式编译`.c`文件，在文件命名时需要注意
2. C++因为函数重载机制，对于函数的链接方式不同，这个影响到C/C++之间的函数调用
3. 在使用new/delete相关运算符时，要进行重载，否则也会产生malloc/free的碎片化问题
4. C++中的模板不能滥用，使用constexpr搭配模板元编程解决运行时开销问题

下面根据实例进行说明。

### C++函数重载机制引发的C/C++链接问题

对于C++来说，为了支持函数重载特性，在链接时默认的机构会包含变量类型的信息。

对于函数foo，在C/C++语言中链接的方式不同，这里展示函数在C/C++中链接的一种方式。

```c
// foo函数, C语言
int foo(int val) => foo

// foo函数，C++语言
int foo(int)      -> _Z3fooi
int foo(float)    -> _Z3foof
int foo(int,int)  -> _Z3fooii
```

在没有任何处理的情况下，C/C++的函数在链接时无法正确找到，会报错`undefined reference`，这里就可以使用`extern "C"`符号，来保证函数声明为C的方式进行链接，即可保证正确的链接。

对于`extern "C"`的使用，主要在头文件中声明，指定在C++编译中使用C链接方式。

具体示例如下所示。

```c
// header.h
#ifdef __cplusplus
extern "C" {
#endif

int foo(int);

#ifdef __cplusplus
}
#endif   
```

通过这样的声明，就表示函数在C++中使用C链接的方式，这样不仅可以在C++中找到正确的C函数。对于能被C访问的C++函数，就需要使用`#include`包含此头文件，才能被正确的链接。不过对于`extern "C"`还可以单独用于函数的声明和定义中。

```c
// 函数声明中
extern "C" int foo(int);

// 函数定义中
extern "C" int foo(int val)
{
}
```

这个方法主要在单独定义某个函数使用C方式链接和调用，可以实现跨C语法的实现，具体示例如下所示。

```cpp
// test1.cpp
class INFO
{
public:
    int a;
    int b;
};

INFO info = {0};

extern "C" int get_info_total(void)
{
    return info.a + info.b;
}

// test.c
int get_info_total(void);

int run_test(void)
{
    int val;
    val = get_info_total();
    return val;
}
```

可以看到，通过直接指定函数的链接方式，就能够在.c中调用接口管理.cpp中才能访问的类参数，解决了混合编程中的链接问题。

### new/delete重载解决碎片化问题

对于C++来说，new/delete是其中十分重要的接口。对于类对象，模板来说，因为有构造函数、析构函数的存在，直接分配空间在把数据拷贝其中是无法执行的；这就需要重载结构体的new/delete函数，从而进行内存的有效管理和控制。

下面给出配合FreeRTOS的new/delete的重载实现。

```cpp
// 线程安全的内存管理函数
class MEM_ALLOC
{
private:
    /* data */
    inline static size_t mem_size = 0;

public:
    static void *new_with_throw(size_t size) {
        void *pT = static_cast<void *>(pvPortMalloc(size));
        if(pT == NULL) {
            std::bad_alloc ba;
            throw ba;
        }
        task_ENTER_CRITICAL();
        mem_size += size;
        task_EXIT_CRITICAL();
        return pT;
    }

    static void *new_without_throw(size_t size) noexcept{
        void *pT = static_cast<void *>(pvPortMalloc(size));
        if(pT == NULL) {
            return nullptr;
        }
        task_ENTER_CRITICAL();
        mem_size += size;
        task_EXIT_CRITICAL();
        return pT;
    }
    
    void *operator new(size_t size) {
        return new_with_throw(size);
    }

    void *operator new(size_t size, const int& id) {
        return new_with_throw(size);
    }

    void *operator new(size_t size, const std::nothrow_t&) noexcept {
        return new_without_throw(size);
    }

    void *operator new[](size_t size) {
        return new_with_throw(size);
    }

    static void delete_ptr(void *ptr, size_t size) {
        if (ptr != nullptr) {
            vPortFree(ptr);
            
            // 更新内存占用
            task_ENTER_CRITICAL();
            mem_size -= size;
            task_EXIT_CRITICAL();
        }
    }

    void operator delete(void *ptr, size_t size) {
        delete_ptr(ptr, size);
    }

    void operator delete[](void *ptr, size_t size) {
        delete_ptr(ptr, size);
    }

    static int get_size()  { return mem_size; }
};

// 继承重载的对象
class INFO: public MEM_ALLOC
{
public:
    INFO() {
    }
    ~INFO() {
    }
    int get_val(void) {return a;}
private:
    int a{1};
};

int foo(void)
{
    INFO *pInfo = new(std::nothrow_t) INFO;
    
    if (pInfo == nullptr)
        return 0;
    
    val = pInfo->get_val();

    delete pInfo;

    return val;
}
```

使用这样方式，就可以在单片机中实现支持多线程安全的存储管理。当然也可以自己实现内存管理函数，从而避免使用系统的malloc/free的碎片问题，导致工作异常。

### constexpr和模板元编程的应用

对于C++来说，模板作为其基础是类复用的常规操作；但是对于单片机来说，使用模板会带来体积膨胀问题，这就需要使用编译期处理和constexpr来实现零成本抽象，从而高效的实现功能。

这里给出使用模板元编程实现驱动的代码。

```c
namespace stm32f4
{
    namespace gpio {
        enum class GPIO_PORT {
            PA = 0,
            PB,
            PC,
            PD,
            PE,
            PF,
            PG,
            PH,
        };            
        
        struct pins_alternate_info {
            gpio::GPIO_PORT port;
            uint32_t pin;
            uint32_t alternate;
        };
     
        template<GPIO_PORT port>
        constexpr GPIO_TypeDef* GPIO_PORT_TO_ADDR(void) {
            if constexpr (port == GPIO_PORT::PA) {
                return GPIOA;
            } else if constexpr (port == GPIO_PORT::PB) {
                return GPIOB;
            } else if constexpr (port == GPIO_PORT::PC) {
                return GPIOC;
            } else if constexpr (port == GPIO_PORT::PD) {
                return GPIOD;
            } else if constexpr (port == GPIO_PORT::PE) {
                return GPIOE;
            } else if constexpr (port == GPIO_PORT::PF) {
                return GPIOF;
            } else if constexpr (port == GPIO_PORT::PG) {
                return GPIOG;
            } else if constexpr (port == GPIO_PORT::PH) {
                return GPIOH;
            } else {
                return nullptr;
            }
        }
        
        template<GPIO_PORT port>
        void clock_enable(void)
        {
            if constexpr (port == GPIO_PORT::PA) {
               __HAL_RCC_GPIOA_CLK_ENABLE();
            } else if constexpr (port == GPIO_PORT::PB) {
               __HAL_RCC_GPIOB_CLK_ENABLE();
            } else if constexpr (port == GPIO_PORT::PC) {
               __HAL_RCC_GPIOC_CLK_ENABLE();
            } else if constexpr (port == GPIO_PORT::PD) {
               __HAL_RCC_GPIOD_CLK_ENABLE();
            } else if constexpr (port == GPIO_PORT::PE) {
               __HAL_RCC_GPIOE_CLK_ENABLE();
            } else if constexpr (port == GPIO_PORT::PF) {
               __HAL_RCC_GPIOF_CLK_ENABLE();
            } else if constexpr (port == GPIO_PORT::PG) {
               __HAL_RCC_GPIOG_CLK_ENABLE();
            } else if constexpr (port == GPIO_PORT::PH) {
               __HAL_RCC_GPIOH_CLK_ENABLE();
            } else {
                // process nothing
            }
        }
                
        template <GPIO_PORT port, int pin>
        class device_gpio {
            static_assert(pin >= GPIO_PIN_0 && pin <= GPIO_PIN_15, "pin number not support");
            protected:
                GPIO_TypeDef* port_{GPIO_PORT_TO_ADDR<port>()};            
                int pin_num_{pin};
               
            public:
                RT_CXX_TYPE init(uint32_t mode, uint32_t pull = GPIO_NOPULL, uint32_t speed = GPIO_SPEED_FREQ_MEDIUM, uint32_t alternate = 0)
                {
                    GPIO_InitTypeDef GPIO_InitStruct = {0};
                    
                    clock_enable<port>();
                    
                    GPIO_InitStruct.Mode = mode;
                    GPIO_InitStruct.Pull = pull;
                    GPIO_InitStruct.Speed = speed;
                    GPIO_InitStruct.Pin = pin_num_;
                    GPIO_InitStruct.Alternate = alternate;
                    HAL_GPIO_Init(port_, &GPIO_InitStruct);
                    
                    return RT_CXX_TYPE::RT_OK;
                }
        };
        
        template <GPIO_PORT port, int pin>
        class DEV_GPIO_OUTPUT : public device_gpio<port, pin> {
            public:
                void high(void) {
                    HAL_GPIO_WritePin(this->port_, this->pin_num_, GPIO_PIN_SET);
                }
                
                void low(void) {
                    HAL_GPIO_WritePin(this->port_, this->pin_num_, GPIO_PIN_RESET);
                }
                
                void toggle(void) {
                    HAL_GPIO_TogglePin(this->port_, this->pin_num_);
                }
        };

        template <GPIO_PORT port, int pin>
        class DEV_GPIO_INPUT : public device_gpio<port, pin> {
            public:
                int data(void)
                {
                    return HAL_GPIO_ReadPin(this->port_, this->pin_num_) == GPIO_PIN_SET?1:0;
                }
        };
    
        //...
}

// main.cpp
// 声明LED所属的引脚
DEV_GPIO_OUTPUT<GPIO_PORT::PB, GPIO_PIN_0> led;

// 进行引脚的初始化
led.init(GPIO_MODE_OUTPUT_PP)

// 进行引脚的翻转
led.toggle();
```

可以看到，使用constexpr和模板元编程，可以在编译期就定义完成I/O，在保证C++便利性的情况下，也没有过多的增加代码，这正是适合单片机开发的C++应用。
